Encapsulation, going down the stack

L7  [               DATA               ]     data
L4  [ TCP ][         DATA             ]     segment
L3  [ IP ][ TCP ][   DATA             ]     packet
L2  [ ETH ][ IP ][ TCP ][ DATA ][ FCS ]     frame
L1   1011 0100 1110 0010 1001 1101 ...      bits
  • The original data never changes. Each layer wraps what it was handed.
  • Only Layer 2 adds a trailer. The FCS checks the whole frame for errors.
  • De-encapsulation is the same thing in reverse at the receiver.
  • The PDU name tells you which header is currently outermost, which tells you which device can act on it.

What changes at each hop

The single highest-value fact in this course Across a routed path, the Layer 2 addresses are rewritten at every hop while the Layer 3 addresses stay the same end to end. A router strips the old Ethernet header and builds a new one for the next link. The IP header rides through untouched, except that TTL drops by one.

Troubleshoot by layer

  1. L1 Is the link light on?
  2. L2 Is the MAC address table showing the device on the port you expect?
  3. L3 Does ipconfig show a real address, mask, and gateway? Can you ping the gateway?
  4. L4 Is the service listening on the port you think it is?
  5. L7 Does the name resolve? Try nslookup.

Work upward from the bottom. A Layer 3 problem is impossible to fix if Layer 1 is broken, and most of the time Layer 1 is what is broken.
