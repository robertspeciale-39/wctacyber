The full forwarding decision

Every frame that arrives at a switch goes through the same two steps.

  1. Learn from the source. Record the frame's source MAC address and the port it arrived on, replacing any older entry for that MAC. (Refresh the aging timer.)
  2. Decide from the destination. Look up the destination MAC.
Destination MAC isSwitch doesName
In the table, on a different port than it arrived onSends out that one port onlyForward
In the table, on the same port it arrived onDrops the frame. The destination is already on that segmentFilter
Not in the table (unknown unicast)Sends out every port except the one it arrived onFlood
FF:FF:FF:FF:FF:FF (broadcast)Sends out every port except the one it arrived onFlood

Two details that decide questions. First, a switch never sends a frame back out the port it came in on. Second, a source MAC address is never a broadcast, so a switch can never learn FF:FF:FF:FF:FF:FF.

Worked example

MAC table:
   Port 1   AAAA.0001
   Port 2   BBBB.0002
   Port 3   (empty)

Frame arrives on Port 1:   src AAAA.0001   dst CCCC.0003

Step 1: the source AAAA.0001 is already on Port 1, so nothing changes (the timer refreshes). Step 2: CCCC.0003 is not in the table, so it is unknown unicast and the switch floods out Ports 2, 3, and every other port except Port 1. When CCCC replies from Port 3, the switch learns that entry, and from then on traffic to CCCC is forwarded, not flooded.

Now a second frame on Port 2: src BBBB.0002 dst AAAA.0001. Source already known. The destination is on Port 1, a different port, so the switch forwards to Port 1 only.

Aging

Table entries do not last forever. If a MAC has not been seen as a source for a while (300 seconds is the default on Cisco switches), the entry is removed. This stops the table filling with devices that left, and it means a device that moves to another port will be relearned there. The table has a limited size, too: a flood of fake source addresses can fill it, which forces the switch to flood everything. That attack is called MAC flooding.

Domains

Two terms get tested a lot.

Collision domainBroadcast domain
MeaningDevices whose transmissions can collideDevices that receive each other's broadcasts
HubOne shared domain for all portsOne
SwitchOne per portOne for the whole switch (per VLAN)
RouterOne per interfaceOne per interface

A switch splits collision domains and does not split broadcast domains. A router (or a VLAN) splits broadcast domains. Counting domains on a diagram: one collision domain per switch port or per link, and one broadcast domain per router interface or per VLAN.

Modern switch ports run full duplex: send and receive at once with no collisions at all. The two ends of a link must agree on duplex and speed. A duplex mismatch produces slow, lossy links that still show "up."

Forwarding methods

  • Store-and-forward receives the entire frame, checks the FCS, then forwards. It drops bad frames. This is the Cisco default.
  • Cut-through starts forwarding as soon as it has read the destination MAC. It is faster and passes along damaged frames because it forwarded before checking.

Commands

Switch# show mac address-table               the table
Switch# show interfaces status               port state, speed, duplex, VLAN
Switch# clear mac address-table dynamic      empty it, then watch it relearn

An exercise worth doing in Packet Tracer: clear the table, run show mac address-table and see it empty, ping between two PCs, and show it again. Then clear it and use Simulation mode to watch the first frame flood and the next one forward. Seeing a flood happen is worth ten paragraphs.
