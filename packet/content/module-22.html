This is the module that ties the course together. Everything from Modules 7, 8, 12, 13, and 14 meets here in one idea, and that idea is the highest-value concept in Round 2. If you leave with one fact, leave with this: across a routed path, the MAC addresses change at every hop and the IP addresses never do.

What Layer 3 does

The network layer moves a packet from its source host to its destination host, across as many networks as it takes. It provides logical addressing (IP), and routers make a forwarding decision at this layer. It does not guarantee delivery or ordering. That is Layer 4's job.

The IPv4 header

You do not need bit offsets, but you need the fields that matter and what they do.

FieldWhat it does
Version4 for IPv4
Source IP addressWho sent the packet
Destination IP addressWho it is for. The router's lookup key
TTL (Time To Live)Decremented by 1 at each router. At 0 the packet is discarded, which stops routing loops
ProtocolWhat is inside: 6 is TCP, 17 is UDP, 1 is ICMP
Header checksumDetects corruption in the header, recalculated at each hop
Differentiated services (DSCP)Priority marking for QoS

IPv6 simplified the header. The TTL became Hop Limit (same job, new name), the Protocol field became Next Header, and the checksum was removed to make routers faster. The addresses grew to 128 bits each.

What a router does to a packet

  1. Receives a frame whose destination MAC is its own interface.
  2. De-encapsulates: strips the Ethernet header and trailer.
  3. Reads the destination IP and looks it up in the routing table.
  4. Decrements the TTL, and if it hits 0, discards the packet and tells the sender.
  5. Finds the exit interface and next hop, ARPs for the next hop's MAC if it does not have it.
  6. Re-encapsulates in a brand new Ethernet header, with its own MAC as the source and the next hop's MAC as the destination.
  7. Sends it out.

The signature table: what changes and what does not

Follow one packet from PC1 to PC2 across two routers. Study how each row of the table differs from the one above it, and which columns never move.

PC1 --- R1 --- R2 --- PC2

Where the frame is        Src MAC    Dst MAC    Src IP     Dst IP
PC1  to R1                PC1        R1-left    PC1        PC2
R1   to R2                R1-right   R2-left    PC1        PC2
R2   to PC2               R2-right   PC2        PC1        PC2

Look at the IP columns: PC1 and PC2 on every row, from end to end. Now look at the MAC columns: different on every row. The MAC addresses describe one hop only. The IP addresses describe the whole journey.

There is one exception worth knowing, and it proves the rule. If NAT is on the path, the router rewrites the source IP too. Without NAT, the IPs never change.

Why the design works

MAC addresses have no structure, so they can only identify a device on the local link. IP addresses have network structure, so a router can look at the network portion of the destination and make a forwarding choice without knowing every device. Each layer does the job it is built for: Layer 2 gets the frame across this link, Layer 3 gets the packet across all the links.

Verifying it yourself

Router# show ip route
Router# show ip interface brief
Router# show arp

Then do the real exercise. In Packet Tracer, open Simulation mode, ping across a router, and click the PDU at each device to open the PDU Information window. Read the Ethernet and IP boxes at every hop and fill in the table above yourself. That is the U4 mastery gate, and no cheat sheet replaces seeing it.
