Module 17 is about discipline. Anyone can run ping. The students who win State run the right tool, in the right order, and can say what the result proved. The competition rewards the method, because the lab is built so that random changes make things worse.

Reply from 192.168.20.5: bytes=32 time<1ms TTL=127

Know the failure messages, because each means something different.

ResultUsually means
Reply from ...Working
Request timed outThe packet was sent but no reply came: no return route, a firewall dropping it, or the target is down. It also appears once at the start while ARP resolves, which is normal
Destination host unreachableA router (or your own host) is telling you it has no route to that network. The problem is on the path or in the routing table
Replies with high time or intermittent lossCongestion, a bad cable, or a duplex mismatch

TTL (Time To Live) starts at a fixed number and drops by one at every router. When it hits zero the packet is discarded. That stops packets from looping forever, and it is exactly how tracert works: it sends packets with TTL 1, 2, 3, and so on, and each router that discards one reveals itself.

The standard diagnostic sequence

Work from the inside out, one layer of distance at a time. The first failure is where the problem is, and everything after it is not worth testing yet.

1. ipconfig                    is the config sane? address, mask, gateway, DNS
2. ping 127.0.0.1              is the TCP/IP stack on this PC working?
3. ping (own IP address)       is the NIC up and configured?
4. ping (default gateway)      can I reach the local network and the door out?
5. ping (remote router/host)   does routing work beyond the gateway?
6. tracert (remote host)       where along the path does it stop?
7. nslookup (name)             if IP works but names do not

Each failure maps to a place to look:

First step that failsWhere to look
Step 1 shows wrong or 169.254 valuesStatic settings, or DHCP (Modules 8, 9, 11)
Step 2 or 3This PC's NIC, driver, or cable (Layer 1 and 2)
Step 4Switch ports, VLAN, wrong gateway (Modules 7, 12)
Step 5Router interfaces, missing or one-way routes (Module 14)
Step 6 stops at hop NThe router at hop N or the link after it
Step 7 onlyDNS (Module 16)

Habits that score points

  • Change one thing, then retest. If you change three things and it works, you do not know which one fixed it and you may have broken something else.
  • Check the lights first. A red or amber link in Packet Tracer is a Layer 1 or interface problem. No amount of IP editing will fix it.
  • Check both directions. A one-way ping failure often means a missing return route.
  • Write down what you found. Competition checklists reward documented findings as well as fixes.

On the Cisco CLI

Router# ping 10.0.0.2
Router# traceroute 192.168.20.5
Router# show ip interface brief       up/up on every link you expect?
Router# show ip route

On a router, ping prints ! for each reply and . for each timeout. !!!!! is success, ..... is none, and .!!!! is the normal first-packet timeout during ARP.

Before you move on

  • Recite the seven-step sequence and say what each step tests.
  • Say what "Request timed out" and "Destination host unreachable" each point to.
  • Explain how TTL makes tracert work.
  • Given a failure pattern, name the next command you would run and why.
