The box your ISP left in your house is four devices in one case. Module 4 pulls it apart, and once you see the four parts separately, home networking stops being mysterious.

The four devices inside one box

  • A modem, translating the ISP's signal into Ethernet. Sometimes this is a separate box.
  • A router, connecting your home network to the ISP's network.
  • A switch, which is what those four LAN ports on the back actually are.
  • An access point, providing the Wi-Fi.

Packet Tracer models this as a single device called a wireless router. Configuring it is GUI work rather than IOS commands, which is why this module has no command list.

WAN port versus LAN ports

This is the part people get wrong, and it is worth being blunt about.

The WAN port (often labeled "Internet") faces your ISP. It gets a public address, usually from the ISP by DHCP. It is one port and it is a different network from everything else on the device.

The LAN ports and the wireless side are all the same network as each other. A laptop on Wi-Fi and a desktop plugged into LAN port 2 are on the same subnet and can reach each other without the router doing any routing at all.

So the wireless router is a boundary with the public network on one side and your private network on the other. Everything on the private side shares one public address through NAT, which Module 12 covers properly.

If a lab tells you the router "can reach the internet but no device on the LAN can," check whether something is plugged into the WAN port that should be in a LAN port. It is the most common cabling mistake in this module.

The configuration order that works

Do it in this order every time. Skipping around is how you lock yourself out of a device mid-lab.

  1. Change the admin password. First, not last. Default credentials for every consumer model are published online, and a competition lab will score this.
  2. Set the WAN side. Usually DHCP from the ISP. Static only if the scenario gives you an address.
  3. Set the LAN side. The router's own LAN address becomes the default gateway for every device on the network. Something like 192.168.0.1.
  4. Configure the DHCP scope. Start address, how many addresses, lease time. Leave room at the low end of the range for devices you want to address statically, like a printer or a server.
  5. Set the SSID. Give it a name that does not identify the household or the room number.
  6. Set wireless security. WPA2 at minimum, WPA3 if offered, with a long passphrase.
  7. Save, then test with a real client. Associate a laptop, confirm it got an address in your scope, ping the gateway.

DHCP, briefly

The router hands each client four things: an IP address, a subnet mask, a default gateway, and a DNS server. Miss any one of them and something breaks in a way that looks unrelated.

No address at all shows up as an APIPA address starting 169.254. That is the client giving up and assigning itself something. When you see 169.254 in ipconfig, the DHCP server did not answer. Do not start editing IP settings by hand, go find out why the offer never arrived.

Module 11 covers the DORA exchange in detail. For now, know the four things a lease delivers and know what 169.254 means.

Why this matters in the competition

The Round 1 lab is built around this module. You will get a wireless router, a client or two, and a requirements list. The scored items are almost always the same set: correct SSID, correct security type, correct DHCP scope, admin password changed, and a client that actually associates and gets an address.

Configure in the order above, then verify from the client. A router that is configured correctly and a client that is actually working are two different claims, and only the second one earns points.
