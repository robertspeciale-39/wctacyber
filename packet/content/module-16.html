The application layer is the part of the network a person actually touches, and Module 16 is the one where you configure services on a Packet Tracer server and then trace what a client does with them. The single most useful fact to leave with: when pinging an IP address works and pinging a name does not, it is DNS.

The client/server model

At this layer, one device runs a program that requests (the client) and another runs a program that answers (the server). Remember from Module 1 that these are roles, not hardware. One PC can be a web client and a file server at the same time.

DNS: names to addresses

People remember names; networks route addresses. The Domain Name System translates between them. A client's resolver asks a DNS server "what is the address for www.example.com?" and the answer comes back as an A record (name to IPv4 address). An AAAA record is the IPv6 version.

  1. You type a name into a browser.
  2. The client checks its own cache.
  3. If it is not cached, it sends a query to the DNS server it was given (usually by DHCP), using UDP port 53.
  4. The server replies with the address.
  5. The browser now connects to that address.

Notice what that implies. The DNS server's address is a setting on the client, and if it is wrong or missing, every name fails while every IP address still works. To a user, "the internet is down." To you, it is one line in ipconfig.

C:\> nslookup www.example.com
Server:   dns.lab
Address:  192.168.10.10

Name:     www.example.com
Address:  192.168.10.20

Configuring services on a Packet Tracer server

Click the server, open the Services tab, and you will see each one in the left list. The tasks the competition uses most:

  • DNS: turn the service On, then add a record with a name and the address it should resolve to, and click Add. Forgetting to click Add is the classic miss.
  • HTTP: turn the service on. The default page is editable under index.html.
  • Email: set a domain name, then create users with passwords under the same tab.
  • FTP: create a user with permissions to read, write, or delete.
  • DHCP: create a pool with gateway, DNS, and start address, and turn the service on.

Then test from a PC. In the Desktop tab, the Web Browser opens by name or address, and the Command Prompt runs nslookup and ping. Always test from a client, because a service that is "on" but unreachable earns nothing.
