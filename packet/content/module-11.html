Module 11 is DHCP. It is a short protocol and it shows up everywhere: quiz questions about the four-message exchange, labs that make you configure a pool, and troubleshooting scenarios where a client has a 169.254 address. Learn the sequence and the five lines of configuration.

What DHCP does

Dynamic Host Configuration Protocol hands out IP configuration automatically. A client does not just get an address. It normally gets four things: an IP address, a subnet mask, a default gateway, and a DNS server. Miss one of the last two and the client can ping local hosts but cannot reach other networks or use names.

Static or dynamic

StaticDynamic (DHCP)
Set byA person, by handA server, automatically
Best forServers, routers, printers, anything others must find at a fixed addressLaptops, phones, and most user devices
RiskTypos, duplicate addressesIf the server is down, clients have no address

A reservation blends the two: DHCP always hands the same address to a given MAC address, so the device is dynamic in setup and fixed in practice.

DORA: the four-message exchange

Memorize it as Discover, Offer, Request, Acknowledge. The order is what gets tested.

#MessageFrom, toDeliverySays
1DiscoverClient to anyoneBroadcast"Is there a DHCP server out there?"
2OfferServer to clientUnicast (or broadcast)"Here is an address you can have."
3RequestClient to serverBroadcast"I accept that offer."
4AcknowledgeServer to clientUnicast (or broadcast)"It is yours for the lease time."

Discover is a broadcast because the client has no address and does not know any server yet. The Request is a broadcast too, which lets any other servers that made an offer know theirs was not chosen. Clients use UDP: the server listens on port 67 and the client on port 68.

Leases

An address is leased, not given. It is good for a set time. Partway through, the client tries to renew with the same server, and if it stops renewing, the address returns to the pool. A short lease suits a coffee shop where devices come and go; a long lease suits a stable office.

Configuring a pool on a Cisco router

Order matters in one place: exclude addresses first, before you build the pool, so the router never hands out the gateway's own address.

Router(config)# ip dhcp excluded-address 192.168.10.1 192.168.10.9
Router(config)# ip dhcp pool LAN10
Router(dhcp-config)# network 192.168.10.0 255.255.255.0
Router(dhcp-config)# default-router 192.168.10.1
Router(dhcp-config)# dns-server 8.8.8.8
Router(dhcp-config)# end

Read it line by line. The first command reserves .1 through .9 for static devices. The pool name LAN10 is just a label. network defines the range to hand out. default-router is the gateway the client will receive, which is an easily forgotten line with a confusing name. dns-server is the DNS the client receives.

Verifying

Router# show ip dhcp binding        who has which address
Router# show ip dhcp pool           pool settings and usage

C:\> ipconfig /release              give the address back
C:\> ipconfig /renew                run DORA again

In Packet Tracer, set a PC's IP Configuration to DHCP and watch it pick up a lease. If it comes up with 169.254.x.x instead, DORA did not complete.

When the client and server are on different networks

Broadcasts stop at routers, so a DHCP server on one network cannot hear a Discover from another. The fix is a DHCP relay: the router interface facing the clients is told where the server is and forwards the request as a unicast.

Router(config-if)# ip helper-address 10.0.0.5     address of the DHCP server

The security angle

A client trusts the first Offer it sees. A rogue DHCP server that answers faster can give clients a bad gateway or bad DNS, quietly steering their traffic through an attacker. The standard defense on a switch is DHCP snooping, which allows Offers only from ports you have marked trusted.
