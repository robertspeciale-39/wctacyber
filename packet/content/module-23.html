Subnetting. This is the highest-value skill in the Semifinals and the place most points are lost, and it is not because it is hard. It is because it has to be fast and exact. You will need Module 20 (binary and the place values) solid before this makes sense. If you are still slow converting, go drill that first.

What you must produce

Given an address and a prefix, you should be able to produce all seven items, on demand, in under a minute.

  1. The subnet mask in dotted decimal.
  2. The network address.
  3. The broadcast address.
  4. The first usable host.
  5. The last usable host.
  6. The number of usable hosts.
  7. The number of subnets, if you are splitting a larger network.

The key numbers

For any prefix, two numbers drive everything.

  • Host bits = 32 minus the prefix. These are the zeros in the mask.
  • Usable hosts = 2host bits minus 2. (One address is the network, one is the broadcast.)
  • Block size (also called the magic number) = 256 minus the mask value in the interesting octet. Equivalently, the value of the last 1 bit in the mask.

Memorize the usable-hosts column and the block sizes together: 128, 64, 32, 16, 8, 4 for blocks, and 126, 62, 30, 14, 6, 2 for hosts. Notice that each is the block size minus 2. A /30 with 2 hosts is the standard size for a link between two routers.

The fast method

Find the interesting octet, the one where the mask is neither 255 nor 0. Subnets start at multiples of the block size in that octet.

Example: what network is 192.168.10.77/26 in?

  1. /26 means mask 255.255.255.192. The interesting octet is the fourth.
  2. Block size is 256 minus 192, so 64.
  3. Subnets in the fourth octet start at 0, 64, 128, 192.
  4. 77 falls between 64 and 127, so the network address is 192.168.10.64.
  5. The next subnet starts at 128, so the broadcast is one less: 192.168.10.127.
  6. First host is network plus 1: 192.168.10.65.
  7. Last host is broadcast minus 1: 192.168.10.126.
  8. Hosts: 26 minus 2 = 62.
Address       192.168.10.77/26
Mask          255.255.255.192
Network       192.168.10.64
First host    192.168.10.65
Last host     192.168.10.126
Broadcast     192.168.10.127
Usable hosts  62

Check it with the binary AND from Module 20: 77 is 01001101 and 192 is 11000000, and the AND is 01000000, which is 64. They agree.

Working across octets

When the interesting octet is not the fourth, the same method works one octet to the left, and the octets after it become 0 (network) or 255 (broadcast).

Address       172.16.45.9/20       mask 255.255.240.0
Interesting   third octet, block size 256 - 240 = 16
Subnets       172.16.0.0, 16.0, 32.0, 48.0 ...
45 is in      32 to 47
Network       172.16.32.0
Broadcast     172.16.47.255
First host    172.16.32.1
Last host     172.16.47.254
Usable hosts  2^12 - 2 = 4,094

Choosing the right size for a requirement

The other half of the module runs backwards. You are told how many hosts a subnet needs and must choose the prefix. Add 2 (network plus broadcast), then find the smallest power of two that is at least that number. The exponent is the host bits, and the prefix is 32 minus it.

2 hosts (a router link)442/30

200 hosts2022568/24

A subnet that is too small leaves devices without addresses. One that is much too large wastes address space. The exam answer is the smallest subnet that still fits.

Splitting a network into subnets

To cut a network into equal pieces, borrow host bits and give them to the network. Each borrowed bit doubles the number of subnets and halves the hosts in each. Subnets = 2borrowed bits.

Split 192.168.1.0/24 into 4 subnets:
  4 = 2^2, so borrow 2 bits  ->  /26, block size 64
  192.168.1.0/26     hosts .1   to .62     broadcast .63
  192.168.1.64/26    hosts .65  to .126    broadcast .127
  192.168.1.128/26   hosts .129 to .190    broadcast .191
  192.168.1.192/26   hosts .193 to .254    broadcast .255

VLSM: different sizes for different needs

Variable Length Subnet Masking means every subnet gets the size it needs, not the same size. The rule that keeps it from overlapping: assign the largest subnet first, starting at the beginning of the address space, then carve each smaller one from what is left.

Given 192.168.1.0/24:  LAN A needs 100, LAN B needs 50, a router link needs 2

LAN A   100 hosts -> /25   192.168.1.0/25     (.0   to .127)
LAN B    50 hosts -> /26   192.168.1.128/26   (.128 to .191)
Link      2 hosts -> /30   192.168.1.192/30   (.192 to .195)
Free space remains from 192.168.1.196 onward.

How to get fast

  • Do ten subnetting problems a day, and time them. Aim for under a minute each.
  • Memorize the block-size and host-count table rather than recomputing it.
  • Always find the interesting octet first.
  • Verify with the AND method until you trust the shortcut.
  • Write the next subnet's start, then subtract one for the broadcast. It is the fastest way to avoid arithmetic mistakes.

Before you move on

  • For 10.1.5.200/27, produce mask, network, broadcast, first host, last host, and host count.
  • Choose a prefix for 25, 60, and 500 hosts.
  • Split a /24 into 8 equal subnets and list them.
  • Lay out the VLSM example above for different host counts, without overlap.
