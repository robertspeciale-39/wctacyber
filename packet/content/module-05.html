This is the most important module in Unit 2. Encapsulation is the idea the rest of the course is built on, and once it clicks, half of the conceptual-application questions in this competition answer themselves.

Protocols and standards

A protocol is a set of rules for communication. Every protocol has to settle the same handful of things: how the message is encoded, what format it takes, how big it can be, how fast it is sent, whether the receiver confirms it arrived, and what happens when something goes wrong.

A standard is a protocol that an organization has written down and published so different vendors can build equipment that works together. Cisco switches talk to HP switches because both follow IEEE 802.3. That interoperability is not luck, it is the entire reason standards bodies exist.

The two models

The OSI model has seven layers and is a teaching and troubleshooting tool. The TCP/IP model has four layers and describes what actually runs on the internet. You need both, because the course and the competition switch between them freely.

Encapsulation

Every layer wraps the data it receives from the layer above in its own header, then hands it down. The receiving device does the same thing in reverse. That wrapping is encapsulation and the unwrapping is de-encapsulation.

Three things to take from that picture:

  • The data never changes. Every layer adds wrapping around it and the original payload rides along untouched.
  • Only Layer 2 adds a trailer. The FCS at the end is an error check on the whole frame. Every other layer adds a header only.
  • The name changes at each layer. Data, segment, packet, frame, bits. Calling a frame a packet is the kind of imprecision that costs a point.

Why the same bytes get different names

Students ask why the course insists on five words for what feels like one thing. Because different devices care about different parts.

A switch reads the Ethernet header and ignores everything inside it. A router strips the Ethernet header, reads the IP header, then builds a brand new Ethernet header for the next hop. Naming the PDU tells you which header is currently on the outside, which tells you which device can act on it.

That idea is the whole of Module 22, and it is the highest-value concept in Round 2. If you understand the picture above, you are already most of the way there.

Before you move on

  • List the seven OSI layers in order, then map the four TCP/IP layers onto them.
  • Name the PDU at each layer without hesitating.
  • Say which layer adds a trailer, and what that trailer is for.
  • In Simulation mode, step one PDU and watch the headers appear. That is the U2 mastery gate, and there is no substitute for doing it.
