Module 14 is where Packet Tracer starts to fight back. Building a LAN is easy. Getting two LANs to talk through a router, then figuring out why they do not, is the skill that wins State. Read the routing table like a sentence and the rest follows.

Why a router is required

Hosts on different networks cannot reach each other directly, because a host only delivers locally and a switch only forwards within one network. A router sits on more than one network, and its job is to move packets from one to another. No router, no communication between networks. It is that simple.

The routing table

Every router keeps a routing table: a list of destination networks and what to do for each. For a packet it looks for the entry that matches the destination, and when several match, it picks the longest prefix (most specific). It does not look at the source address at all.

Router# show ip route
Codes: C - connected, S - static, L - local, * - candidate default

Gateway of last resort is 10.0.0.2 to network 0.0.0.0

C    192.168.10.0/24 is directly connected, GigabitEthernet0/0
L    192.168.10.1/32 is directly connected, GigabitEthernet0/0
C    10.0.0.0/30 is directly connected, GigabitEthernet0/1
S    192.168.20.0/24 [1/0] via 10.0.0.2
S*   0.0.0.0/0 [1/0] via 10.0.0.2

Where entries come from

LLocalAutomatically, the router's own interface address as a /32

S*Static defaultYou type it, a route to 0.0.0.0/0

Note the first row carefully: a connected route appears only if the interface is up/up. A forgotten no shutdown means the route is missing, and everything behind that interface is unreachable.

Configuring static routes

A static route says "to reach this network, send packets to this next hop." You provide the destination network, its mask, and either the neighbor's address (next hop) or your own outgoing interface (exit interface).

Router(config)# ip route 192.168.20.0 255.255.255.0 10.0.0.2
                         dest network   mask         next hop

Router(config)# ip route 0.0.0.0 0.0.0.0 209.165.200.226
                         default route: match everything, send it here

Router(config)# ipv6 route 2001:db8:acad:2::/64 2001:db8:acad:99::2

The default route 0.0.0.0/0 matches any destination, and because it is the shortest possible prefix, it only wins when nothing else matches. This is the "gateway of last resort," and it is what you point at your ISP.

Administrative distance is how much the router trusts a source when two sources offer a route to the same network. Lower wins. Connected is 0, static is 1, OSPF is 110, RIP is 120. This is why a static route overrides a dynamic one.

Return paths: the part everyone forgets

Routing is two-way. A ping needs a route from A to B and a route from B back to A. If you configure only one direction, the packet arrives, the reply is dropped, and the ping times out. It looks as if the forward path is broken when it is the return path.

PC1 ---- R1 ====== R2 ---- PC2

R1 needs:  ip route (PC2's network)  via R2
R2 needs:  ip route (PC1's network)  via R1       the one people forget

Rule of thumb for a one-way failure: when a ping works in one direction only or times out with the forward route obviously correct, check the other router for a missing route back.

Verifying

Router# show ip route
Router# show ip route static          only the static entries
Router# show ip interface brief       are the interfaces up/up?

Start with show ip interface brief. If an interface is down, nothing else matters. Then show ip route. Then ping.
